## D1. `slot_ts`의 타임존 표현

**선택지**

| | 저장 | 비용 |
|---|---|---|
| ① `timestamptz` (UTC 저장) | Postgres가 UTC로 정규화, 조회 시 `AT TIME ZONE` | 사람이 쿼리 결과를 읽을 때 변환이 필요 |
| ② `timestamp` + KST 고정 | 눈으로 읽기 쉬움 | 타임존이 **컬럼에 적혀 있지 않음.** 다른 소스가 붙으면 암묵 전제가 깨짐 |

**사실 2개**
- **GitHub Actions 러너는 UTC**입니다. 수집기가 로컬 시각으로 슬롯을 계산하면 슬롯이 9시간 밀립니다
- **ASOS `tm`은 KST이고 타임존 표기가 없습니다** (`2010-01-01 10` 형태). 두 소스를 조인하는 순간 변환이 어딘가에서 일어납니다

**권고 — ①.** 저장은 UTC `timestamptz`로 통일하고, **KST는 "달력일 경계"에서만 등장**시킵니다.

```
수집기        slot_ts = floor(datetime.now(timezone.utc), 10min)     ← UTC
랜딩          slot_ts timestamptz                                     ← UTC
ASOS staging  (tm || ':00') AT TIME ZONE 'Asia/Seoul'  → obs_ts       ← KST 입력, UTC 저장
dim_date      date_key = (slot_ts AT TIME ZONE 'Asia/Seoul')::date    ← KST 달력일
```

**네 곳에서 같은 규칙입니다**: 저장은 UTC, 달력일 해석은 KST 단 한 지점(`date_key` 계산). `dim_date`의 "하루"가 KST 자정 기준이라는 것은 이 한 줄로 결정됩니다.

② 를 고르시면 수집기에서 `ZoneInfo("Asia/Seoul")`을 명시해야 하고(러너가 UTC이므로 생략하면 틀립니다), ASOS 변환이 사라지는 대신 "타임존이 어디에도 안 적혀 있다"는 상태가 남습니다.

## D2. 같은 `slot_ts`에 관측이 둘 들어오면 무엇을 남기나

Actions cron은 지연·중복 실행이 있습니다. 확정된 멱등 경로는 `ON CONFLICT DO NOTHING`이고, 그건 **먼저 쓴 행이 이깁니다.**

**선택지**

| | 동작 | 위험 |
|---|---|---|
| ① `DO NOTHING` 유지 + **부분 수집을 커밋하지 않음** | 첫 번째 완전한 스냅샷이 이김 | 수집기 쪽에 원자성 책임이 생김 |
| ② `DO UPDATE WHERE excluded.fetched_at > ...` | 나중 관측이 이김 | **"중복 투입 0건"이 멱등성 증거가 못 됩니다** — 재적재가 행을 바꿉니다 |
| ③ 슬롯 완결성 플래그 + 마트에서 제외 | 나쁜 슬롯이 남지만 표시됨 | 창고에 신뢰할 수 없는 행이 남음 |

**권고 — ①.** 이유는 멱등성 증거와의 일관성입니다.

멱등성 검증을 "같은 구간을 두 번 적재했을 때 두 번째 `INSERT` 영향 행수 = 0"으로 쓰기로 했습니다. ②를 고르면 두 번째 적재가 행을 **바꾸므로** 그 숫자가 0이 아니고, 증거의 정의부터 다시 써야 합니다. "멱등하다"와 "최신이 이긴다"는 양립하지 않습니다 — 하나를 골라야 합니다.

①의 전제는 **수집기가 3페이지 전부 성공할 때만 S3에 쓴다**는 것입니다. 이게 깨지면 ①은 "더 나쁜 관측이 영구히 남는" 최악의 선택이 됩니다. 그래서 이 결정은 수집기 쪽 원자성과 **한 묶음**입니다 — W2 수집기 검증 기준에 "부분 페이지 커밋 0건"을 넣으세요.

③은 ①과 배타적이지 않습니다. `mart_station_hourly.observed_slot_cnt`(기대 6)가 이미 그 역할을 하므로 **①을 쓰면서 완결성은 마트에서 드러납니다.** 추가 컬럼이 필요하지 않습니다.

> **승계 조건 (2026-11-06, [PAR-17](/PAR/issues/PAR-17) 지적 ③)**
>
> 리뷰에서 "그 전제를 강제하는 로더 코드가 레포에 **아예 없다**"는 판정이 나왔습니다. 맞습니다 —
> 수집기가 미착수이므로 지금 "부분 수집 미커밋"은 **아무것도 보장하지 않습니다.** 즉 D2는
> 현 시점에 결정일 뿐이고, 그 결정이 성립할지는 W2에서 갈립니다.
>
> **W2 수집기 카드를 만들 때 검증 기준에 아래 한 줄이 반드시 들어가야 합니다.**
> 들어가지 않으면 D2는 ②로 되돌리는 쪽이 안전합니다 — 전제 없는 ①이 최악이기 때문입니다.
>
> - `부분 페이지 커밋 0건` — 3페이지 중 하나라도 실패하면 S3에 아무것도 쓰지 않음을
>   **실패 주입으로** 확인(2페이지 성공 + 3페이지 500 → 랜딩 행수 증가 0).

## D3. `dim_station` snapshot의 소스

문제의 원인: **`bikeStationMaster`에 대여소 명칭이 없습니다** (필드 5개 — `RNTLS_ID`·`ADDR1`·`ADDR2`·`LAT`·`LOT`). 즉 차원 속성이 두 곳에서 옵니다.

| 속성 | 출처 | 주기 |
|---|---|---|
| 명칭 · 거치대 수 | **`bikeList`** | 10분 |
| 주소 · 자치구 · 좌표 | **seed** | 수동 재발행 |

dbt snapshot은 소스 테이블 **하나**를 봅니다.

**선택지**

| | 추적 가능 | 비용 |
|---|---|---|
| ① 실시간 staging | 명칭·거치대수 | 10분마다 snapshot 스캔 (144회/일) |
| ② seed | 주소·좌표 | **명칭을 추적할 수 없습니다** — SCD2의 유일한 추적 대상이 빠짐 |
| ③ 중간 뷰 `int_station_current` | 둘 다 | 뷰의 **갱신 시점이 snapshot의 해상도**가 됨 |

**권고 — ③, 해상도는 1일.**

`int_station_current` = staging에서 대여소별 **최신 슬롯의 명칭** + seed LEFT JOIN(주소·자치구·좌표). snapshot은 **KST 하루의 마지막 슬롯 이후 1일 1회** 실행합니다.

근거 둘입니다.
- `check_cols`가 **`station_name` 하나뿐**이고 명칭 변경은 드뭅니다. 10분 해상도로 추적할 대상이 아닙니다 — ①은 144배의 스캔으로 같은 결과를 냅니다
- 해상도를 1일로 **명시**하면 "명칭이 언제 바뀌었나"의 답이 "그날 중"으로 고정됩니다. 해상도를 적어두지 않으면 그 질문에 답할 수 없습니다

②는 고르실 수 없다고 봅니다 — SCD2를 쓰면서 추적 대상이 없으면 차원이 SCD1과 같아집니다.

**함께 따라오는 확정 규칙** (재결정 불필요): 자치구는 `check_cols`에서 **무조건 제외**(seed 재발행 노이즈), `rack_tot_cnt`는 24시간 안에 플랩하므로 차원이 아니라 **fact 측정값**.

## D4. 서로게이트 키를 쓰는가 — fact가 무엇을 참조하나

**설계서 문장 그대로 구현하면 끊깁니다.** 설계서는 `LAG(parking_bike_cnt) OVER (PARTITION BY station_sk ORDER BY slot_ts)`를 썼는데, SCD2에서 `station_sk`는 **버전마다 바뀌는 키**입니다. 명칭이 한 번 변경되면 그 대여소의 시계열이 버전 경계에서 끊기고, 끊긴 자리에서 `delta`와 `est_rentals`가 비거나 튑니다.

**선택지**

| | fact가 참조 | 조인 | 윈도우 파티션 |
|---|---|---|---|
| ① fact가 `station_id`만 (**권고**) | 자연키 | `station_id` + 유효기간 범위, 또는 `is_current` | `station_id` — 안전 |
| ② fact가 `station_sk`만 | 버전 키 | 등가 조인 (간단) | **깨짐** |
| ③ fact가 둘 다 (Kimball durable key) | 둘 다 | 등가 조인 가능 | `station_id` |

**권고 — ①.** `station_id`는 `ST-xxxx` 형태의 안정적이고 의미 있는 자연키입니다. 별도의 불변 대리키를 만들 이유가 없습니다.

- 현재 상태 조회(마트 대부분)는 `dim_station WHERE is_current`로 등가 조인과 비용이 같습니다
- 시점 정합 조회만 유효기간 범위 조건이 붙습니다 — 그 쿼리가 드물고, 범위 조건이 **"그 슬롯 당시의 명칭"이라는 의도를 코드에 드러냅니다**
- `station_sk`는 **차원 행 식별자로만** 남깁니다(dbt snapshot이 만드는 `dbt_scd_id` 역할). fact는 참조하지 않습니다

③(둘 다 들고 역할 분리)도 방어 가능합니다 — 표준 Kimball 패턴이고 등가 조인이 가능해집니다. 대신 fact에 컬럼이 하나 늘고 **로더가 적재 시점의 `sk`를 조회해야** 하므로 적재 경로가 차원에 의존하게 됩니다. 멱등 적재를 단순하게 유지하려면 ①이 가볍습니다.

②는 고르지 마세요. 설계서가 그걸 전제했다는 사실이 이 문서의 존재 이유입니다.

## D5. `dim_date`의 공휴일 출처

설계서는 공휴일 플래그를 전제하는데 **소스가 정해져 있지 않습니다.** 출처 없이 플래그만 만들면 테스트가 거짓말을 합니다.

**선택지**

| | 비용 | 한계 |
|---|---|---|
| ① 손으로 쓴 seed csv (**권고**) | 10분 | 범위를 넘으면 조용히 틀립니다 |
| ② data.go.kr 특일정보 API | 신청 1건 + 수집 코드 | 범위 밖 작업이 늘어남 |
| ③ 공휴일 빼고 주말만 | 0 | 설계서 전제가 깨짐. 연휴 수요 패턴을 설명 못 함 |

**권고 — ①, 단 두 가지 조건.**

- csv에 **출처 URL과 발행일을 주석으로** 적습니다 (행정안전부 관공서 공휴일 고시)
- **수집 기간 + 1년**을 채우고, `dim_date`에 `date_key > (seed 최대일)` 이면 **빌드가 실패하는 테스트**를 걸어둡니다

두 번째가 핵심입니다. ①의 **범위** 위험은 "범위를 넘었는데 아무도 모르는 것"이고, 테스트 한 줄로 그 위험이 없어집니다. 그 테스트가 없으면 ①은 시한폭탄이고, 있으면 6주 프로젝트에서 ②보다 나은 선택입니다.

> **남는 공백 — 내용의 정확성 (2026-11-06, [PAR-17](/PAR/issues/PAR-17) 지적 ④)**
>
> `assert_holiday_seed_covers_dim_date`는 **범위만** 봅니다. seed에 적힌 날짜가 **맞는지는
> 어떤 테스트도 보지 않습니다.** 음력 기반 공휴일(설날·부처님오신날·추석)은 조용히 틀리는
> 종류이고, 하루 밀린 설날은 모든 테스트를 통과합니다. 자동 검증 경로가 없으므로 절차로 막습니다.
>
> **seed를 채운 뒤 아래를 수행하고 csv 주석에 수행일을 적으십시오.**
>
> 1. 행정안전부 관공서 공휴일 고시(또는 `data.go.kr` 특일정보) 원문과 **연도별로 1:1 대조**
> 2. 대체공휴일 적용 여부를 연도별로 확인 — 규칙이 해마다 바뀝니다
> 3. 대조에 쓴 고시 URL과 발행일을 csv 주석에 남김 (출처 없는 날짜는 검증 불가)
>
> 대조가 끝나지 않은 연도는 seed에 넣지 마십시오. 넣지 않으면 범위 테스트가 빌드를 세워
> "아직 안 했다"가 드러납니다 — 틀린 날짜를 넣는 것보다 낫습니다.

## D6. 미매칭 자치구 라벨을 `accepted_values`에 포함시킬지

`'미매칭'` 버킷으로 두기로 확정돼 있습니다. 남은 것은 테스트 목록에 **포함시킬지**입니다.

| | 미매칭이 드러나는 곳 |
|---|---|
| ① 25개 + `'미매칭'` 포함 (**권고**) | 마트 수치 + 별도 상한 테스트 |
| ② 25개만 | **테스트 실패**로 |

**권고 — ①.** 단, 이 권고는 **상한 테스트가 실제로 실행되는 동안에만** 성립합니다.

`accepted_values`가 `'미매칭'`을 허용하는 순간 그 테스트는 미매칭을 **무한히** 허용합니다. 미매칭률이 0%에서 100%로 치솟아도 통과합니다. 그래서 ①은 "양을 보는 테스트가 따로 있다"를 조건으로만 고를 수 있습니다. 조건이 깨지면 ①은 안전장치 없이 라벨만 허용하는 선택이 되고, 그건 ②보다 나쁩니다.

> **⚠️ 정정 (2026-11-06, [PAR-17](/PAR/issues/PAR-17) 독립 리뷰 지적 ①)**
>
> 이 절은 처음에 **"미매칭률 상한 테스트가 이미 있습니다"**라고 썼습니다. **사실이 아니었습니다.**
> 실제 상태는 `docs/model/schema-tests.planned.yml`에 `expression: "1 = 1  -- TODO"` 자리표시자였고,
> 그 파일은 `model-paths` 밖이라 **dbt가 읽지도 않습니다.** 즉 ①의 유일한 근거가 공집합이었고,
> 상시 통과하는 테스트조차 실행되지 않는 상태였습니다. 리뷰어 지적이 정확했습니다.
>
> **조치** — 안전장치를 dbt가 실제로 실행하는 위치로 옮겼습니다:
> `dbt/tests/assert_unmatched_gu_rate_within_cap.sql`. 임계는 파일럿 **이전에** 고정한
> **10%**이고(측정 후 임계를 정하면 그건 임계가 아니라 현재 상태의 기록입니다),
> 파일럿 후 "실측률 + 2%p"로 **좁히는** 방향만 허용합니다. 넓히려면 그 이유를 여기에 먼저 씁니다.
> `schema-tests.planned.yml`의 마트 단계 자리표시자는 제거했습니다 — 날짜 그레인 버전은
> `mart_gu_daily`가 생기는 주차에 실측값으로 추가합니다.

②를 고르면 같은 사실에 대해 신호가 두 개가 되고, `accepted_values`가 **상시 빨간불**이 됩니다 — 미매칭은 0이 되지 않습니다(마스터 3,434건 > 실시간 ~2,800건, 구조적 차이).

상시 실패하는 테스트는 **아무도 보지 않게 됩니다.** `accepted_values`는 "`마포구`가 유효한 자치구 문자열인가"라는 도메인 테스트로 두고, "미매칭이 너무 많은가"는 상한 테스트가 봅니다. 두 테스트가 서로 다른 것을 묻는 쪽이 일관됩니다.

②도 방어 가능합니다 — "미매칭은 예외이고 빌드를 세워야 한다"는 입장이면 그쪽입니다. 다만 그 입장은 상한 테스트와 중복이고, 상한값이 이미 "어느 정도는 정상"을 전제합니다.

## 추가로 정한 것 — §6에 없지만 리뷰 항목인 것들

§6 7건 밖이지만 모델 문서에 적혀 있어야 하는 항목입니다. 전부 되돌릴 수 있습니다.

### A. `rack_tot_cnt = 0`의 비율 계산

대여소 단위 거치율은 **`NULL`**(0이 아님). "거치대가 없다"와 "거치율 0%"는 다른 사실이고, `0`으로 두면 자치구 평균을 끌어내립니다. 자치구 집계(`occupancy_rate = Σparking ÷ Σrack`)에서는 **분모에서 제외**합니다.

표본 5건에 `rack = 0`은 없었습니다 — 폐쇄 직전 대여소에서 나올 수 있는 값이고, 전수 확인 항목입니다.

### B. ASOS QC 플래그 — 보존합니다

`fct_weather_hourly`에 플래그 컬럼으로 **남깁니다.** 버리고 격리 조건으로만 쓰면 "왜 이 행이 격리됐나"를 창고 안에서 설명할 수 없습니다.

품질 계층의 순서가 바뀝니다 — **기온 범위를 직접 잡기 전에 소스 플래그를 먼저 씁니다.** 기상청이 "이 관측은 검사에서 걸렸다"고 표시한 것이 본인 룰보다 정확합니다. 그 위에 본인 룰을 얹는 것이 순서입니다. **자전거 쪽은 플래그가 없으니 직접 룰을 만듭니다** — 두 소스를 다르게 취급한 근거가 이것입니다.

**`tsQcflg`는 철자가 다릅니다.** 9종 중 `taQcflag`·`rnQcflag`·`wsQcflag`·`wdQcflag`·`hmQcflag`·`paQcflag`·`psQcflag`·`ssQcflag`는 `Qcflag`인데 지면온도만 **`tsQcflg`**(`a` 없음)입니다. 리네임 맵을 `f"{m}Qcflag"`로 생성하면 **이 한 줄만 조용히 NULL**이 됩니다 — 예외도 테스트 실패도 없습니다. **명시적 딕셔너리로 적고 생성하지 않습니다.**

### C. seed 좌표 `0.0` → NULL

`ST-1001`(서서울호수공원)이 `LAT: 0.0, LOT: 0.0`입니다. **5건 중 1건.**

- `not_null`은 **통과합니다** — 값이 있기 때문입니다
- 그 좌표는 기니만 해상입니다. 자치구 중심 좌표를 내면 바다로 끌려갑니다
- `stg_station_master`에서 `NULLIF(lat, 0)` 변환 + 서울 범위 테스트(`accepted_range` 위도 37.4~37.7 / 경도 126.7~127.2). 범위 테스트가 `0.0` 센티넬과 오타 좌표를 같이 잡습니다

전체 3,434건 중 몇 건인지는 정식 키로 전수 확인해야 합니다. **5건 중 1건이 20%라는 뜻은 아닙니다.**

좌표를 분석에 쓰지 않으신다면 **seed에서 빼는 것도 선택**입니다 — 쓰지 않을 컬럼을 커밋하는 것도 결정입니다.

### D. 랜딩 테이블은 dbt source입니다

`raw.bike_status` · `raw.weather_hourly`는 **dbt 모델이 아닙니다.** DDL은 `sql/migrations/001_*.sql` + `make migrate`, 파티션은 로더가 `CREATE TABLE IF NOT EXISTS … PARTITION OF`. dbt는 `sources:`로 선언만 합니다.

이유: dbt가 소유하면 `dbt run`이 랜딩을 **재생성**할 수 있고, 그러면 원문 보존과 멱등 적재의 PK가 dbt 실행에 걸립니다.

## §5 확정 규칙 — 재결정하지 않음

인용만 합니다. 바꾸시려면 보드 결정이 필요합니다.

| 항목 | 확정 내용 |
|---|---|
| 멱등 적재 | `COPY` → TEMP → `INSERT … SELECT … ON CONFLICT DO NOTHING` |
| 자치구 | `dim_station` **속성**. `dim_gu` 차원 만들지 않음. 미매칭은 `'미매칭'` 버킷 |
| SCD2 `check_cols` | 자치구 **무조건 제외**. 24h 안에 변하는 컬럼은 fact 측정값으로 |
| 파생 fact 행 | `delta = 0` 슬롯도 **행 생성** |
| 조인 방향 | `bikeList` 기준 **LEFT JOIN** seed |
| 미매칭률 상한 | 파일럿 실측률 **+2%p**, 최소 1%p 여유 |
| 완결성 임계 | `warn` 기준선 90% / `error` 70% |
| 검증 기준 | 그레인이 **컬럼 튜플**로 선언 + `unique_combination_of_columns`가 `schema.yml`에 **미리** 작성 |

## 추정치의 한계 — 모델 문서에 남깁니다

`est_rentals` / `est_returns`는 **추정치입니다.** 10분 간격 재고 차분이므로:

- **재배치 트럭과 이용자 대여를 구분할 수 없습니다.** 트럭이 10대를 걷어가면 `est_rentals = 10`입니다
- **같은 슬롯 안의 상쇄가 보이지 않습니다.** 5대 나가고 5대 들어오면 `delta = 0`이고 추정 대여는 0입니다 — **실제 대여 수의 하한**입니다
- **이전 슬롯이 결측이면 `delta`는 `NULL`**입니다 (`prev_slot_present = false`). 결측 슬롯을 0으로 메우면 가짜 반납이 생깁니다

이름을 `est_`로 시작한 것이 이 한계의 표시이고, 마트 컬럼명도 `sum_est_rentals`로 유지합니다. **`rentals`로 줄이지 마세요** — 줄이는 순간 추정치가 사실로 읽힙니다.
